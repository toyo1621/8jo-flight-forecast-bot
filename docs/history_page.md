# 過去の予測と運航結果

- GitHub Pagesの公開範囲は、日本時間の前月・前々月（例: 11月中は9月・10月）。当月の終了済みの日付や3か月以上前の日別履歴は配信しない。今日・今後の予報は従来どおり掲載。
- 履歴一覧・便別ページの履歴・日別HTML・サイトマップを同じ範囲にする。再ビルドには空の出力先を使用する。公開検証はサイトマップにない古い日別HTMLを検出する。
- 保存済みデータは削除しない。運航スコアに使う類似実績、欠航傾向の集計、予測精度の評価期間はこの公開範囲の制限と別。
- 一覧は新しい日付順。各日に対象3便の保存スコアと結果を表示。
- 運航は緑、欠航・引き返しはオレンジ、未取得はグレー。文字でも状態を区別。
- 引き返しは欠航件数に重複計上しない。未取得は確認済み件数から除外。
- 月と結果条件はAND。集計は表示中の日付だけが対象。JS無効でも全件と初期集計は読める。
- 気象詳細は保存済みJMA入力を表示し、現在の予報や係数で過去値を再計算しない。
- 収集テーブルの気象は観測と確認できないため、実測天気と呼ばない。欠測は記録なし。
- 適用係数は保存内訳のみを表示。保存内訳にある履歴全件等は公開HTMLへ展開しない。
- DB変更なし。既存の公開確認済み・legacyの選別条件は維持する。

## 管理者の全期間閲覧

BigQueryの読み取り・クエリ実行権限がある環境で、依存パッケージを導入し、Application Default Credentialsを設定してからリポジトリのルートで以下を実行する。

```sh
python -m flight_forecast.export_forecast_archive
```

表示された `file://` URLを自分のブラウザで開く。保存済みの全期間を同じ月・結果絞り込みと日別詳細で確認できる。読み取り専用の処理で、予測の再計算・保存・公開は行わない。出力はアクセスを絞ったローカル一時ディレクトリに作成し、GitHub Pagesや共有フォルダには置かない。

`bigquery.jobs.create` の403が出る場合は、BigQueryを閲覧できるだけでなくクエリも実行できる管理者アカウントのADCを使う。管理者はBigQuery Studioから保存テーブルを直接確認することもできる。

この公開制限は現在配信しているページを対象とする。過去に第三者が保存したコピー、検索エンジンのキャッシュ、すでに作成されたActionsの成果物は取り消せない。

検証: tests/test_history_usability.py、既存静的生成テスト。
ブラウザで360px/1280px幅、月変更、欠航・未取得条件、空状態、詳細開閉を確認。
プレビューfixtureは架空のスコア・気象を含むテスト用。実運航評価には使用しない。
