# 八丈島便 運航の目安・表示ロジック仕様書

## 1. 値の位置づけ

画面に表示する%は、対象便と同じ便の過去実績に、予報気象とルールベースの補正を適用した**未校正の運航統計参考値**です。Brier score、信頼度曲線、時系列外部検証は未実施であり、実際の運航確率や航空会社の判断を示しません。

内部APIの`probability`という名称は互換性のため維持しますが、利用者向けには「統計参考値」と表示します。

## 2. 母集団と基礎値

対象便ごとに、BigQuery上の同じ便だけを母集団にします。

1. 風向差30度以内、風速差3 m/s以内を検索します。
2. 5件未満なら風向差45度以内、風速差5 m/s以内へ広げます。
3. それでも5件未満なら同じ便の全履歴を使います。
4. `運航`・`運航(条件付)`は1、`欠航`・`条件付き→引返欠航`は0として平均します。
5. 未取得、空、未対応ステータスは0とせず、保存・集計から除外します。

有効な履歴が5件未満の場合は統計参考値を算出せず、`calculation_status=insufficient_history`、`probability=null`、件数、理由コードを返します。画面には97%や記号を表示せず「算出不可」と表示します。算出不可の値には気象補正、台風補正、低確率色、モデル比較の数値化を適用しません。

## 3. 気象補正

主予報にはOpen-Meteoの`jma_seamless`を指定し、気象庁(JMA)のGSM・MSMモデルを使用します。JMAモデルで提供されない最大瞬間風速と視程だけはOpen-Meteo標準予報で補完し、JMA由来の値は上書きしません。補完を取得できない項目は欠測として扱い、画面へ通知します。比較欄にはGFS・ECMWF・JMAを併記し、JMA欄は台風補正後の主予報値とリスク要約を再利用します。

| 条件 | 倍率 |
| --- | ---: |
| 視程5 km未満 | 0.60 |
| 視程3 km未満 | 0.45 |
| 降水量2 mm/h以上 | 0.85 |
| 降水量8 mm/h以上 | 0.70 |
| 低層雲量80%超 | 0.90 |
| 低層雲量95%以上 | 0.75 |
| 最大瞬間風速15 m/s以上 | 0.90 |
| 最大瞬間風速20 m/s以上 | 0.55 |
| 突風補正に該当せず、平均風速10 m/s以上 | 0.90 |

突風と平均風速の補正は重複適用しません。風向120〜240度かつ平均風速9 m/s以上では「南風注意」を表示しますが、その条件だけでは値を下げません。最終表示の範囲は0〜97です。

これらは運航基準ではなく仮説的なしきい値です。週次の時系列分割評価で妥当性を確認しますが、サンプル不足時は統計的な結論を出しません。

## 4. 台風影響度

[八丈島・東京方面 台風影響目安](https://8jo-typhoon-ensemble.toyo1621.workers.dev/?source=jma)のJMAモードから、日別の`targets.flight.riskLevel`を取得します。

| API値 | 表示 | 倍率 |
| --- | --- | ---: |
| `low` | 補正なし | 1.00 |
| `medium` | 台風接近リスク小 | 0.90 |
| `high` | 台風接近リスク中 | 0.80 |
| `severe` | 台風接近リスク大 | 0.70 |

外部APIは`riskLevel`だけでなく、飛行機向けの`score`、`factors`、`inputs`、`scoreConfig.version`を返します。本アプリはこれらを日付別に保存し、`riskLevel`だけを持つ旧キャッシュや因子内訳のない応答は数値補正に使いません。APIは当日を含む11日分を必要とします。日付が欠けている場合は`low`と推測せず、その日は補正なしとして欠測通知を表示します。API全体が失敗した場合は、7時間以内のキャッシュだけを利用できます。

外部APIと本アプリの因子は次のように対応します。

| 外部APIの因子 | 本アプリの因子との重複 | 現在の扱い |
| --- | --- | --- |
| `wind` | 平均風速・突風 | 重複候補として記録し、weather-only / typhoon-only / combinedを比較 |
| `rain` | 降水量 | 重複候補として記録し、時系列評価で確認 |
| `wave` | 直接の対応因子なし | 台風側の内訳として保存 |
| `typhoonApproachProbability` | 台風接近そのもの | 台風影響度の説明因子として保存 |
| `ensembleSpread` | アンサンブル天候信頼度 | 台風側と本アプリ側を別々に保存 |

因子内訳がある場合だけ、feature flag `TYPHOON_NUMERIC_ADJUSTMENT_ENABLED=true`（既定値）でリスク倍率を適用します。サンプル不足や検証期間ではこのflagを`false`にすると、台風接近リスクを注意表示だけにできます。適用前の基礎値、気象因子、台風因子、適用後の値、外部因子内訳は、予測スナップショットの`factor_breakdown_json`へ保存します。係数の妥当性は未校正のため、運航基準とはみなしません。

## 5. 予報シナリオの一致度

GFS最大31メンバーとECMWF最大31メンバーを混ぜず、モデル別に統計参考値を再計算します。各モデルについて10・50・90パーセンタイル、中央80%幅、受信member数、期待member数、予測計算に使えたmember数を保存します。GFSとECMWFの両方が必要member数を満たした場合でもpoolせず、各モデルを同じ重みで比較し、最悪のgradeを日次要約へ採用します。片方だけが利用可能な場合は`source=ensemble_partial`として表示し、両方不足の場合は`source=unavailable`、`grade=null`、表示「評価不可」とします。

各モデルの変数について、memberから提供された割合、member間で実際に変動した変数、member内で一定だった変数、JMA主予報で固定した件数、部分欠測を追跡します。memberにない視程や低層雲量をJMA値で補った場合は、`baseline_fixed_variables`または`partially_missing_variables`と注意表示へ含めます。これはシナリオのばらつきの指標であり、運航結果の正確さや信頼区間ではありません。

| 等級 | 中央80%幅 |
| --- | ---: |
| A | 10ポイント以内 |
| B | 20ポイント以内 |
| C | 30ポイント以内 |
| D | 40ポイント以内 |
| E | 40ポイント超 |

これは気象シナリオ間のばらつきであり、予測精度や運航確率の信頼区間ではありません。モデル別の有効memberが10件未満の場合はA〜Eを作らず、lead timeは別の注意情報としてのみ表示します。

## 6. データ品質と時刻

- 運航結果と気象値はBigQueryだけへ保存します。
- 当日の3便と必須気象値がすべて揃うまで保存しません。
- 入力`NULL`で既存の正常な気象値を上書きしません。
- 同一ステータスの既知欠航理由を`未確認`で上書きしません。
- 予測スナップショットの`weather_field_sources_json`には、JMA主予報、Open-Meteo補足、欠測、旧データの出所不明をフィールド単位で保存します。
- 便・到着時刻・予報参照時刻は`app_config.FLIGHTS`を唯一の情報源とします。
- 予報参照時刻はANA1891が8時、ANA1893が13時、ANA1895が17時です。
- 表示する更新時刻は、実際に使用している予報バンドルの取得時刻です。
